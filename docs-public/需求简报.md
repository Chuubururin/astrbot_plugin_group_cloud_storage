# 需求简报

> 全项目唯一需求基准（V-型裁剪 Type B：原 BRD+PRD 合并件）。其余文档说明「如何实现与验证」。
> 需求语义冻结：修改本文件的需求条款须走甲方变更流程（HL-04 三处同步）。

## 1. 一句话定位

**群云存储（Group Cloud Storage）**：QQ 群原生三类存储空间——**群文件**（目录树文件系统）、
**群相册**（图片/视频）、**群精华**（消息存档）——统一建模、索引、检索与转移，构成每个群的云端存储池。

**第一目标（2026-09-02 所有者订正，G-1）**：**多账号群文件统一管理，独立维护元数据支持
增删改查，云（群文件）到云（openlist）的双向桥，存储空间计算与统计，文件格式转换**。
其基础仍是把三类空间统一建模为「群云存储池」——云端是唯一数据源，本地只保存可编码化的
元数据索引；文件内容仅在上传、下载、中转、校验时按需流经本机，不持久化本地副本；
一切资源可用稳定 URI（`cloud://<群号>/<类型>/<id>`）引用。

## 2. 存储模型（v2.0 冻结）

| 存储空间 | QQ 侧形态 | 本插件建模 | 可管理操作 |
| --- | --- | --- | --- |
| 群文件 | 目录树 + 文件 | 资源类型 `file`（path/ext 文件系统化） | 上传/下载/改名重传/移动/删除/新建目录 |
| 群相册 | 相册 + 媒体 | 资源类型 `album`（meta.album_id 关联） | 上传（图片/分段视频）、媒体查看 |
| 群精华 | 精华消息 | 资源类型 `essence`（长文本分段，meta.parts） | 文本保存、删除、全文重建 |
| OpenList 网盘 | 外部存储 | 桥接双向转存（remote_path 稳定引用） | 浏览/转存/标记/索引 |

> **并列语义（所有者确认，D-1/T 系列）**：文件/相册/精华是**并列的资源类别**——文件可存一切；
> 相册只能存图片与视频；精华只能存文字。任何把三者混排为单一列表、以类型筛选区分的设计
> 不符合该语义（八 Tab 信息架构见 §5）。

### 2.1 三条铁律

1. **云端是真源（source of truth）**：本地 SQLite 仅保存元数据索引（现行 schema v16，
   见 [数据与编码规范](../tech/%5B设计%5D%5B研发%5D数据与编码规范.md)）；文件内容只在传输/校验时流经本机，**不持久化本地副本**。
2. **一切资源可编码化引用**：`cloud://<群号>/<类型>/<id>`；程序与文档引用资源一律用 URI。
3. **本地索引可随时重建**：删库不丢数据，`/cssync` 全量重建；云端删除经对账同步到本地
   （软删 + 合成资源保护）。

### 2.2 三条通道（StorageGateway）

| 通道 | 方向 | 用途 |
| --- | --- | --- |
| 云端通道 | OneBot API（NapCat/SnowLuma） | 真源读写：同步、上传、下载直链、精华、相册 |
| 本地通道 | SQLite 索引 + 本机下载服务 | 元数据检索 + 对外 HTTP/FTP 下载（配置 `download_server_*`） |
| 外部通道 | HTTP/FTP/SMB | 拉取入库（`/csfetch`）；出库由 OpenList 桥接承担（v2.13 裁定） |

## 3. 目标用户

| 用户 | 诉求 |
| --- | --- |
| 资源池所有者 | 集中管理 300 群、快速检索、容量调度 |
| 外部客户端/程序 | 经 http/ftp/smb 接口读写云端文件 |
| 群成员 | 浏览、下载群资源 |

## 4. 角色与权限（三层）

| 角色 | 层级 | 能力 |
| --- | --- | --- |
| 群成员 | `GROUP_MEMBER` | 本群只读查询 |
| 群管理员（owner/admin） | `GROUP_ADMIN` | 本群管理命令（/cssync /csfiles /csfile…）、文件增删改、精华管理 |
| 全局管理员 | `GLOBAL_ADMIN` | 跨群查询/管理（配置 `global_admin_qqs`） |

授权规则（`PermissionService.can_manage`，同步判定）：目标群须在受管范围
（`managed_groups` **白名单空 = 放行所有群**）；本群操作需 GROUP_ADMIN；跨群需 GLOBAL_ADMIN。
命令处理器不自含权限判断；Page 端走 `is_page_managed`（403 语义）。契约细节见接口契约 §3。

### 5.1 【文件】

存储符合要求的**任意格式文件**；群文件（云侧）信息扫描；凋零动态更新列表（待实现）；
操作以 OneBot 11 API 为基准，组合 API 实现各种文件管理操作；文件资源编码化（cloud:// URI）；
文件信息、文件搜索（**完整文件名搜索**）、文件标签（独立索引/标签，目标态拆分）、
**按类型筛选（13 类分类）与状态筛选**；**大文件集**（>95MB 分卷压缩逐一上传，
列表以语义化大文件名呈现，见 §5.9）。

**分类 13 类（2026-09-01 定稿）**：全部 / 文稿 / PDF / 表格 / 幻灯片 / 在线文档 / 图片 / 视频 /
音频 / 压缩包 / 安装包 / 闪传文件 / 文件夹 / 其他；分类后缀支持在配置中编辑
（`type_ext_overrides` 通道，默认表 13 类数据驱动）。**文件夹只有一级**：文件只能在文件夹或
根目录；文件夹单独归为一类（列表目录行恒为「文件夹」类，不参与扩展名判定）。

**状态筛选（2026-09-01 定稿）**：在网盘 / 在相册 / 在精华消息 / 未下载（派生状态，
SELECT 只读不写库；判定以资源 id 关联优先、文件名+大小兜底）。

并入的历史功能（F-3.x/F-4.3/F-6.x）：上传（≤95MB 直传 / >95MB 分卷）、下载（流式/分卷重组）、
改名重传（唯一改名路径）/移动/删除/新建目录、两段式上传、批量操作（删除/移动/标签/直链）、
目录过滤与真面包屑、框选多选、URL 拉取入库（http/https/ftp/smb）、云端大文件转分卷。
**上传来源矩阵见 §5.12；下载分发见 §5.14（2026-09-02 增补：下载到本地/直链(转 ftp·smb·http)/到网盘/
图片视频到相册/文本到精华）**。

### 5.5 【任务】（后端 v15 切片 1 + 前端视图 views/tasks.js 均已落地）

管理正在进行的任务流：**继续、暂停、中断、撤销**已完成或进行中的任务；**撤销任务恢复执行前
状态**；**记录操作流**，操作流同样支持暂停、继续、中断和撤销。定时任务（各种扫描）受管控
（可见/可中断/可暂停调度）；**插件配置功能独立，不在此列**。衔接 ADR-0005（台账）与
ADR-0006 D-6（可逆性矩阵；删除类云端不可逆，明示「不可撤销」）。

已落地（2026-08-31 切片 1）：op_ledger 台账（pending/running/paused/retry/done/failed/cancelled
+ 启动对账白名单续传）、op_ops 操作流（移动/改名/删除/标签埋点）、四动作端点
`tasks`/`tasks/queue`/`tasks/pause`/`tasks/resume`/`tasks/interrupt`/`tasks/undo`/`tasks/ops`
（SSE 增补 paused/resumed）；撤销矩阵：排队未执行=丢弃，移动=反向移动，改名=原状恢复，
标签=快照恢复（可翻转），删除类=明示不可撤销。

分卷/分片目的：防过期与绕过单条上限；重组经下载后按语义化标识完成（C-6）；校验卷与压缩为
**可选能力**（C-4/C-5）。规则全文、现行实现差距见[入库与组合存储](../tech/%5B设计%5D%5B研发%5D入库与组合存储.md)。

### 5.10 缺省规则（2026-09-01 定稿，操作范式缺省基准）

1. **未选群/账号**：群组未选择时默认选中**全部在线账号与全部群组**；文件、相册、精华
   各自支持查询全部（per-module 筛选状态，D-3）；
2. **排序**：未选择排序方式时默认**修改时间由新到旧**（`created_at desc`）；
3. **分栏**：未选择分栏模式时默认**单栏**（用户显式选择后记忆，双栏能力保留）；
4. **上传目标群**：未指定群名/群号时——群文件默认使用**群号值最小且剩余空间大于待上传文件**
   的群；群相册默认群号值最小的群（上限未知）；精华默认群号值最小的群（上限未知）。

### 5.11 渲染设计（2026-09-01 定稿）

1. 列表符合**文件管理器设计**：提供 `../` 返回上一级（群文件单级文件夹；根目录不显示）；
2. 颜色样式风格与 astrbot 原版相同；**同步 astrbot 亮色和暗色模式，支持跟随系统**
   （bridge 上下文 theme 优先，`prefers-color-scheme` 回退）。

### 5.14 下载分发矩阵（2026-09-02 重构，ADR-0009 W2-A）

以「目标分发」视角统一四模块下载操作（全部经 OpQueue 任务，可见/可中断，D-6）：

| 目标 | 文件 | 相册 | 精华 | 网盘 |
| --- | :-: | :-: | :-: | :-: |
| 本地 | 有（流式/重组） | 有（媒体直链） | 有（全文组装） | 有（直链） |
| 直链 http | 有 | 有 | 有 | 有 |
| 直链 ftp | 本机下载服务地址（FTP 虚拟目录） | 同左 | 同左 | 同左 |
