# 架构总览

> 范式：**轻量 DDD（限界上下文）+ 六边形架构（端口-适配器）+ 领域事件流**。
> 隔离会变的部分：OneBot 实现端、持久化实现、外部存储（OpenList）、限速策略。

## 限界上下文（模块边界）

| 上下文 | 职责 | 关键概念 | 实现 |
| --- | --- | --- | --- |
| **资源目录**（核心域） | 资源建模、查询、统计、检索、快照 | Resource、Snapshot、ResourceType | SqliteMetaStore + SearchKV（FTS） |
| **采集**（支撑域） | 全量/增量扫描、事件索引、同步任务 | SyncJob、Cursor、互斥锁 | group_scan + resource_sync |
| **文件操作**（支撑域） | 上传/下载/增删改、零整治理 | Composition、Volumes | file_ops + composition |
| **桥接**（支撑域） | 群↔网盘双向转存、网盘索引标记 | BridgeTask、archive_map、netdisk_meta | bridge + netdisk + openlist adapter |
| **权限**（支撑域） | 三层授权 | PermissionLevel、can_manage | permission |
| **调度与风控**（支撑域） | 队列、限速、能力探测降级 | OpQueue、kind 注册、CapabilityState | op_queue + op_dispatch + limiter |
| **对外服务**（支撑域） | 本机 HTTP/SFTP 下载、Page API | DownloadServer、webapi 薄壳 | download_server + webapi |

> 规则：上下文间只通过端口或服务接口通信；命令/路由处理器是薄壳（parse → 授权 → service）。

## 六边形纪律

- Adapter 一律返回 DTO（dataclass），**禁止裸 JSON 上浮到 core**；
- core/application 禁止直接 `event.bot.call_action(...)`（OneBot 只能从 Adapter 出口进入）；
- 外部存储只经 OpenList 适配器（SSRF 防护/重登录/DTO 在此层）。

**能力探测**：CapabilityState 枚举（UNKNOWN / SUPPORTED / UNSUPPORTED / BROKEN）；首次使用前探测，失败进入指数退避；UNSUPPORTED 触发可解释降级，不崩溃。

## 领域事件流（轻量，仅解耦与审计）

```
- 命令同步：SyncRequested → (lock[group]) → GroupFileListed(complete?) → ResourceIndexed×N
                              → FsInfoFetched → SnapshotSaved
- 事件索引：GroupFileUploaded(event) → ResourceIndexed(1)
- 查询统计：StatsRequested → StatsComputed（SQL 聚合）
- 队列进度：OpStateChange → SSE data_changed（节流，前端统一调度刷新）
```

> 事件用 dataclass + service 内直调实现，只用于解耦与日志，**不引入事件总线**。

## 一致性规则

- **幂等 UPSERT**：`(group_id, type, source_ref)` 唯一键，ON CONFLICT 保留 status（不复活）。
- **孤儿清理门控**：仅全量遍历 `complete == true` 执行 `mark_missing_as_deleted()`；
   部分失败禁止清理；合成资源（meta.volumes / kind=text_split）永不清理。
- **同群互斥**：每群一把 `asyncio.Lock`；重复 `/cssync` 返回"运行中"；事件索引不占全量锁。
- **软删除**：源侧消失 → `status=deleted`，保留审计。
- **快照只追加**：Snapshot 不可变。
- **URL 不持久化**：直链实时生成，DB 无 url 列。
- **台账隔离**：桥接状态只存 archive_map，禁写 resources.status。
- **数据凋零**：常规维持 = 事件驱动新增 + 目录级差分对账；云侧消失条目
   立即剔除（软删）；账号离线/更换 → 该账号群组**隐藏**而非删除；定时/全量扫描降级为
   手动例外（受任务管控）。

## 一致性边界：需要静默期的操作

整体替换一个正被并发读写的存储时，"事务原子性"不够 —— 还需要先让在途读者退出
（quiesce / drain），否则会读到"旧表已 DROP、新表尚未填好"的中间态。

两条换库路径的动文件方式不同，未 quiesce 时的失败形态也不同：

| 路径 | 动文件方式 | 在途写的下场 |
| --- | --- | --- |
| `reset_and_rebuild` | `os.replace(tmp, db_path)`（换 inode，旧文件被 unlink） | 提交到**已 unlink 的旧 inode** ⇒ **静默丢失**（不报错） |
| `restore` | `src.backup(dst)` **原地覆盖活库** | 提交到覆盖之后的活库 ⇒ **混合状态** |

现行防护：`ConnectionManager` 维护在途调用计数并提供**有界** `drain()`；
`SqliteMetaStore._reset_and_rebuild_locked()` 与 `IntegrityMixin.restore()` 都在
`close()` 与动文件之间 `await drain()`。`_rebuild_lock` 另外串行化并发重建。

仍然存在的限制：`drain()` 只覆盖"已经进入 store"的调用，不停队列投递，也不拒绝
窗口内新到达的调用 —— 新调用撞上 `RuntimeError: connection manager is closed`，
经 `webapi/compatibility.py` 的统一兜底变成一次 500。这是**响亮的失败**，不是
静默损坏，但窗口内的请求确实会掉。

可达性：`DatabaseAdminService.reset()` 当前没有任何调用方（无 `database/reset`
路由、无前端引用），所以 rebuild 路径是**死代码**；真正可达的是 `database/restore`
路由（需 `database_admin_token`）。

## 设计取舍

以下三处经逐条核实属**有意设计**，改动前需先推翻既有契约：

1. `restore_all_groups()` 的 SQL 是 `UPDATE groups SET managed=1 WHERE removed=0 AND managed!=1`
   —— **用户主动移除的群（`removed=1`）不会被恢复**。这是启动自愈：只修复被离线检测
   误伤（`removed=0` 但 `managed!=1`）的群，不覆盖用户的手动决定。代价是自愈窗口内
   可见性、统计、操作三者对"已移除但仍在库里"的群不一致。
2. `openlist.py` 把 `mkdir` 的 **405 视为"目录已存在"**（REQ-07 幂等契约，
   由 `tests/unit/test_openlist.py` 固定）。改成"先 stat 再决定"会改变对外语义。
3. `webapi/routes.py` 的 `auth` 字段是**声明式**的，见 `接口契约.md` 的「鉴权模型」。
