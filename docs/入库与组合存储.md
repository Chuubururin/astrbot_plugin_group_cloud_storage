# 入库与组合存储设计

> 应对 QQ 单条上限的「拆分存储」体系：云上为零（分片实体）、文件管理为整（完整形态）。

## 三路拆分统一编码（composition 描述符）

| kind | strategy | 云端实体 | 重组方式 |
| --- | --- | --- | --- |
| `volumes` | binary（>95MB 分卷，95MB/卷 `.partNN`；**目的：防过期与绕过单条上限**；压缩可选） | 群文件 | 下载后按**语义化文件名标识**重组 + 逐片/整文件 SHA-256（校验卷可选） |
| `video_segments` | >600s **无损切割**为 <599s/段 | 群文件（volumes 表） | 下载后 ffmpeg 重组为完整长视频 |
| `text_split` | >4000 字符分片，每片 ≤4000（QQ 实限 4500，**预留标记预算**）；按段落→标题→汉字序号切分 | 群精华消息 | **末尾语义化标记**整合为逻辑长文本（下载后重组） |

```json
{"composition": {"kind": "volumes", "parts": 3, "strategy": "binary",
                 "total_sha256": "...", "marker": null}}
```

- 读侧兼容形态：`{"volumes": true}` → volumes；`{"kind": "text_split"}` → text_split
- 分片引用：volumes 表（分卷/视频，含逐卷 status 供断点续传）或 `meta.parts`（精华）

## 拆分口径

| 资源 | 直接上传阈值 | 超限拆分 | 逻辑呈现 |
| --- | --- | --- | --- |
| 精华文本 | **<4000 字符** | >4000 按**段落/标题/汉字序号**分片为 ≤4000 小文本逐个上传（设精+回读验证+重发） | 末尾语义化标记整合为逻辑长文本；重建全文；字符统计 |
| 相册视频 | **<599s** | >600s **无损切割**为多个 <599s 视频逐一上传 | 语义化标题翻译为逻辑长视频；逐段 sha256 → ffmpeg 重组 |
| 群文件 | **<95MB** | >95MB 分卷压缩逐一上传（压缩可选） | 文件名语义化翻译为逻辑大文件；**列表显示大文件名而非分片名** |
| 群组 | 在线账号 | 账号离线/更换 → 该账号群组**隐藏**（非删除） | 列表仅显示在线账号的群（凋零动态更新） |

### 可选能力

- **压缩（可选）**：分卷文件压缩后上传群文件——**下载后解压可逆**；媒体文件重新压制后上传
  群相册——**下载不可逆，操作前必须显式警示**。默认关闭。
- **校验卷（可选）**：分割文件附加**校验卷**，确保完整**上传前与下载重组后一致**
  （在逐片 SHA-256 之上的增强，覆盖分片在云端损坏/被清理的场景）。

## 入口与流向（化整为零 / 化零为整）

- **化整为零入口**：`files/convert-volumes`（云端大文件→分卷）、上传 mode=text（文档文本→精华分片）、
  mode=video+to_album（媒体分片→群相册）
- **转换归属校验**：`convert-volumes`（手动与定时清扫同一规则）仅接受
  **当前群归属账号上传**的资源——`uploader_id` 与群记录 `account_id` 均非空且相等
  （`VolumeMixin._is_current_account_upload`）；缺失身份一律安全侧拒绝（手动路径抛
  ValueError"仅支持当前群归属账号上传的文件进行分卷"，定时清扫记 debug 日志跳过）。
  动机：跨账号下载/上传分片会产生不可管理的残留件；
  本地 `_do_upload` 自动分卷不受影响（目标群即上传账号所在群）。
- **入库**：`fetch`（URL 拉取，http/https/sftp/smb → 群文件；图片可入相册，`upload_image_to_qun_album`）
- **化零为整**：列表以完整形态单行表达（组合描述符判定）；分卷/视频重组经本机下载服务分发

## 传输通道

| 通道 | 语义 | 实现 |
| --- | --- | --- |
| 浏览器下载 | 页面流式下载（分卷/视频重组） | files/download |
| 下载直链 | QQ CDN 直链复制（外部 HTTP 交付） | files/link |
| 本机下载服务 | HTTP `GET /download?group&id&token`（单文件 302→CDN，分卷/视频流式）+ SFTP 虚拟目录 `/<群号>/<文件名>` | 本机下载服务模块 |
| URL 拉取入库 | 外部文件进入云端池 | http(s)/sftp/smb |

（外部获取统一走本机下载服务与 OpenList 桥接；无中转推送/出库导出通道。）

## 关键约定

- **会话句柄**：NapCat file_id 为进程内随机句柄（24h TTL/重启失效）；一切按 ID 操作在操作时
  用实时列表按「名称+大小」解析新鲜 id，删除类操作对已消失目标容错
- **对账保护**：孤儿清理/相册精华对账不删除合成资源（meta.volumes 分卷/视频父资源、
  meta.kind=text_split 自建精华）
- **精华消息 ID**：设精/移精用 send 返回的原始 message_id（非精华条目 id）
- **相册上传**：`upload_image_to_qun_album`，`album_name` 被 NapCat 忽略（落默认相册）
- **富媒体会话**：QQ 重启后消息正常但文件传输可能失效（rich media transfer failed），
  需重新登录恢复（非插件缺陷，故障时下载/上传接口返回明确错误）

## 重组

下载时根据语义化标识自动重组，无需用户干预：

- **分卷文件重组**：下载群文件时，根据语义化文件名标识识别分卷，按序拼接重组为原文件；逐片/整文件 SHA-256 校验确保完整性。若启用了压缩，重组后自动解压还原。
- **分片视频重组**：下载群文件时，根据语义化标题识别视频分片，经 ffmpeg 重组（流复制，无重编码）为完整长视频。
- **分片文本重组**：下载精华消息时，根据文末语义化标记识别文本分片，按序整合为完整长文本。

## 已知限制

- NapCat used_space 恒 0 → 容量=文件索引 SUM
- 相册删除/改名无 API；消息免打扰/隐藏会话/消息通知未开放
- 视频分段当前为重编码（crf23/veryfast），目标为无损切割；耗时与时长成正比
- 超长单消息可能被 QQ 内部切段，重建结果在切点处可能有空白/单字符差异
- 下载服务依赖宿主机网络可达性
